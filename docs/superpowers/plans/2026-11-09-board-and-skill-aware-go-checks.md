# Board- and Skill-Aware Go Checks (Server) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** For allowlisted users, every "go" check rates a row with the user's skill (null becomes beginner) and saved boards, through a learner-aware character gate, and `/api/surf/call` reports when the beginner default applied.

**Architecture:** One env flag with an allowlist is read only where a `userId` is in scope, one time per request or per loaded profile. The result goes down as an explicit, optional context (`goChecks`, `learner`, `skillAware`, `boardClasses`). A missing context runs today's code, so the shared scorer, gate, character and engine never read the env. Each site keeps two skills: a rating skill for the scorer, gate, window shape and engine, and the raw profile skill for copy and audience fields.

**Tech Stack:** Next.js App Router, TypeScript, Supabase (PostgREST reads only), Jest (`@jest-environment node`, SWC, no type-check).
