## Implemented contract

`acquireProviderRunReceipts` in `lib/alerts/swell-watch/provider-run-store.ts` copies and validates every declared source point before any I/O. It fetches the pinned existing Single Runs model sequentially, reuses the strict response parser and stores the full set in the existing atomic receipt RPC. Failure at any source produces no partial storage call. Scope mutation while awaiting a response cannot change the declared batch. The local cap is 500 source points; production scope/throughput remains a separate reviewed contract.

Acquisition does not attest, complete or enqueue anything. The returned IDs identify unqualified stored receipts. Provider run/revision deduplication and constituent equality remain enforced by the existing database contract. No legacy serving source selection changes.

`attest_swell_watch_provider_run` is an owner-only, security-invoker SQL entry point for a separately reviewed evidence decision. PUBLIC, anon, authenticated and service_role have no execute permission. It takes a caller-generated decision ID, exact revision-set ID, accepted/rejected/revoked state, reviewer, evidence hash, provider-contract reference and optional revoked decision ID. Exact retries return the original decision; a different payload with the same ID fails. Acceptance of a superseded revision fails. Revocation uses the existing same-subject trigger and per-provider-run lock, shared with completion/release. Rejected decisions do not implicitly revoke earlier accepted decisions: use explicit revocation IDs for that operation.

An owner decision is a trust boundary, not automatic scientific proof. Before accepting real evidence the reviewer must establish the response/run binding, expected scope and full component coverage, canonical serving relevance and NOAA/Open-Meteo continuity, entitlement and source provenance. A hash or fixture is insufficient. No accepted real decision was created here. The simulated accepted/revoked decisions exist only inside disposable PostgreSQL tests.

`completeAttestedProviderRun` separately calls the existing completion RPC and rejects malformed or mismatched returned identities. The database must still find a current, unrevoked accepted attestation. Corrections/retries cannot become independent temporal confirmations. This function does not manufacture identity prefixes locally or grant release authority.
