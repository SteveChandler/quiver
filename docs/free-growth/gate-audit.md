## Core Loop And Rubric

Core free loop: check the call -> log a session -> get a tuned next call.

Deterministic rubric:

- BLOCKS the core loop -> SOFTEN or FLAG-OFF.
- Operator pre-decision: the alert wall in `lib/alerts/entitlements.ts` `canCreateRule` (`free=home-beach-only`) -> SOFTEN to about 3 free watched rules total, including home.
- TEASES but does not block -> KEEP.
- ALIGNED free-grant / earn-Pro -> KEEP/EXPAND.
- EDGE CEILING already sane, such as favorites=3 -> KEEP.
- Infra-cost-sensitive if opened -> never unlimited; SOFTEN only to a capped ceiling.

## Decisions Summary (039 Work-list)

1. SOFTEN: Alert watched-rule wall across web and native. Replace the current home-beach-only free alert rule gate with about 3 free watched rules total, including home. Keep it capped, not unlimited, because every watched rule can add alert evaluation, notification queue, push, and email cost. Apply consistently to `lib/alerts/entitlements.ts` `canCreateRule`, `/api/alerts/rules`, native `WatchSpotButton`, condition-alert creation surfaces, and any anonymous alert capture finalization mirror.
2. FLAG-OFF: Surf discovery best-spot hard gate. Ensure `SURF_DISCOVERY_BEST_SPOT_GATE` is off for the free-growth phase, or otherwise stop emptying free recommendations. The current flag path blocks the check-call loop by returning only a locked teaser instead of the ranked spot list.
