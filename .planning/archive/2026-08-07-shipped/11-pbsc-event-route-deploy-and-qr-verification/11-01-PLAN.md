<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Request headers -> server render | User-agent is untrusted input used only to choose CTA branch. |
| Browser -> localStorage | Anonymous pending waitlist intent is stored client-side before auth. |
| Browser -> server action | Authenticated users call `joinAndroidWaitlist` to update their own profile. |
| Client analytics -> `/api/events` | CTA tracking sends metadata and must not block navigation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-01 | Spoofing | `app/pbsc/page.tsx` user-agent branch | accept | User-agent spoofing only changes CTA presentation; no authorization or entitlement decision relies on it. |
| T-11-02 | Tampering | Android waitlist intent metadata | mitigate | Keep `joinAndroidWaitlist` Zod bounds for `source`, `surface`, and `placement`; tests assert PBSC values are preserved. |
| T-11-03 | Repudiation | PBSC iOS/Android CTA analytics | mitigate | Use existing tracked CTA components and PBSC metadata so clicks/impressions are attributable. |
| T-11-04 | Information Disclosure | Anonymous waitlist localStorage | mitigate | Store only source/surface/placement/created_at, no PII or secrets. |
| T-11-05 | Denial of Service | `/pbsc` dynamic render | accept | The route is lightweight and no database read is added; production proof catches routing regressions. |
| T-11-06 | Elevation of Privilege | `joinAndroidWaitlist` profile update | mitigate | Preserve `withAuthenticatedAction` and `.eq("id", user.id)` ownership constraint. |
| T-11-SC | Tampering | Package installs | mitigate | No package-manager install tasks are allowed in this plan. |
</threat_model>
