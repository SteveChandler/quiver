## Why this is a separate lane

These deletions are useful because they reduce the native code and test surface before Phase 20.1 changes Home, Beach Detail, Week Scout, watching, and exact return. They are **not** part of the retention hypothesis and must not be mixed into the Phase 20.1 product implementation commits.

Each cleanup slice must be:

- rebased or recreated from current `quiver-native/main` after the release/inflight audit;
- implemented as one isolated commit and preferably one small PR;
- free of unrelated formatting/refactors;
- verified against the exact current reference graph;
- independently revertible with `git revert <slice-commit>`;
- attributed separately from later retention metrics.

The names and estimated line counts below come from the tech-debt audit input. The connected GitHub view did not expose these exact files on pushed `main`, so agents must locate them in the local branch/worktree and compare them with current `main` before claiming they exist or deleting anything.

## Required preflight for every slice

Run from the identified `quiver-native` worktree:

```bash
git status --short
git rev-parse HEAD
git merge-base HEAD main
git rev-list --left-right --count main...HEAD
git diff --name-status main...HEAD
```

Then establish the candidate's exact reference graph:

```bash
# Exact file/name search. Add symbol variants discovered in the audit.
find . -type f \( -name '<candidate-file>' -o -iname '*<candidate-symbol>*' \)
git grep -n '<candidate-symbol>' -- ':!node_modules' ':!.expo' ':!coverage'
rg -n '<candidate-symbol>|<legacy-copy-or-test-id>' src __tests__ tests .maestro scripts 2>/dev/null || true
```

Before deletion, record:

```text
candidate path(s)
branch-only or present on current main
production imports
re-exports/barrels
lazy/dynamic imports
test imports
Maestro/test-ID references
documentation/scripts/config references
replacement/live owner, if any
```

A slice becomes **superseded/no-op** when the files are already absent from current `main` or when the local branch finding no longer applies. Do not recreate a file merely to delete it.

## Execution order

Recommended order:

```text
TD-00 branch/worktree freeze and exact-path inventory
  -> TD-01 nearest-beach removal
  -> TD-02 stale startup prefetch removal
  -> TD-04 retired forecast prototype removal

TD-03 payoff-card removal may run after TD-00 in parallel only when its boat-only
file ownership is disjoint from TD-02 and a safe boat E2E environment is reserved.
```

TD-02, TD-04, and TD-05 should be serialized because they are likely to touch Home, Beach Detail, onboarding hierarchy, recommendation policy, or overlapping tests. Freeze exact file ownership after TD-00 rather than relying on these estimated boundaries.
