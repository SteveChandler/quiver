## Allowed dispositions

Choose exactly one disposition for every logical branch slice:

- **Reference only** — use findings; no code lands.
- **Land audit artifacts** — preserve durable research, issue maps, or validation.
- **Cherry-pick bounded fix** — only for a directly required BFR blocker with isolated tests.
- **Rebase and open a separate PR** — coherent technical-debt work independent of Phase 20.1.
- **Run cleanup slice** — one of TD-01 through TD-05, executed as an isolated deletion PR from current `main`.
- **Superseded/no-op** — current `main` already removed or replaced it.
- **Retire** — no durable value remains after evidence capture.
- **Blocked** — references, ownership, or safe verification are unresolved.

Do not merge the entire branch because its name contains “audit” or because the cleanup list is high-confidence.

## Cleanup execution rules

- Start every slice from current `quiver-native/main` after release/branch truth is reconciled; do not use the stale audit branch as the merge base by default.
- One slice equals one isolated commit and preferably one small PR.
- Do not mix Phase 20.1 feature implementation into cleanup PRs.
- Run an exact obsolete-reference scan before and after deletion.
- Use the repository's canonical test and typecheck commands discovered from current `package.json`.
- Roll back with `git revert <slice-commit>` so deleted files/tests are restored exactly.
- Mark a slice `superseded/no-op` if current `main` already removed it.
- Mark a slice `blocked` if a responsibility lacks a live owner or a safe validation environment is required but unavailable under release policy.
- Attribute cleanup effects separately from later retention experiments.
