**Snapshot date:** 2026-08-24

**Purpose:** Prevent Phase 20.1 from duplicating, overwriting, or falsely treating merged code as released behavior.

> This is a time-bounded release-truth snapshot. Refresh it at the start of Plan 20.1-01, again before any production or native release action, and whenever `main`, `prod`, a release branch, or an overlapping PR changes.

## Status vocabulary

| Status | Meaning |
|---|---|
| **Released and verified** | Present in the actual production/web or distributed native artifact, with the required live/device evidence. |
| **Merged to main** | In the repository default branch only. This does **not** prove production deployment, OTA inclusion, binary inclusion, migration application, or all-user flag state. |
| **Promotion pending** | An open PR or release operation still separates the code from the production branch/channel. |
| **Release branch only** | Work exists on a release/cherry-pick branch and may not be in `main`. |
| **Implementation pending** | Issue/spec exists, but the required product behavior is not complete. |
| **Verification pending** | Code exists, but production, migration, attribution, physical-device, or causal evidence is still missing. |
| **Independent** | Valid work that must not be pulled into Phase 20.1 unless a direct dependency is proven. |

## Executive finding

There is no single branch that represents “everything users have.” Both repositories have branch and release divergence:

- Web `main` and `prod` are not linear. The current comparison is **diverged**; an open `main -> prod` promotion PR contains a bounded email/SEO change set. Phase 20.1 must not infer production state from `main` alone.
- Native `main` and `release/ota-build16-main-parity-20260822` are **diverged**. At this snapshot, `main` is 53 commits ahead while the release branch is 16 commits ahead, with merge base `0f644d74708ba57f2ed309c1a75405111de33676`. A merge to `main` is therefore not proof that an OTA/binary contains the change.
- Several issues remain open after partial fixes because migration application, flag activation, production telemetry, exact web counterpart, or physical-device verification is still outstanding.

Phase 20.1 must create and maintain a **release truth matrix** instead of using Git merge state as a release proxy.
