# Phase 20.1: Durable Beach Follow And Surf-Call Retention Loop - Validation

**Created:** 2026-08-24
**Status:** Required release evidence

## Validation Objective

Prove that durable beach ownership and a watched-call loop increase useful repeat behavior without:

- treating all coastal visitors as surfers;
- damaging water-temperature, tide, or beach-page intent;
- hiding public utility behind signup;
- creating duplicate favorites, alerts, links, or session systems;
- increasing noisy notifications;
- silently changing native recommendation context;
- claiming retention or learning without causal evidence.

No implementation plan is complete from unit tests alone. The phase requires web behavior evidence, cross-surface attribution, native device evidence, and a measured rollout.

## Primary Success Metrics

The planner must define exact queries before implementation. The minimum release scorecard is:

| Metric | Initial target | Notes |
|---|---:|---|
| Eligible beach-page follow rate | >= 3% | Denominator is exposed eligible visitors, not all site traffic |
| Anonymous follow completion after start | >= 70% | Must not require account |
| Followed-beach visitors returning in 28 days | >= 12% | Compare with matched/holdout eligible visitors |
| Surf-qualified exact-handoff start rate | >= 2% | Denominator is surf-qualified web visitors |
| Eligible handoff -> joined native first open | >= 80% | Requires handoff token coverage |
| Joined first open -> exact context resolved | >= 90% | Excludes legitimately expired/removed windows with explicit fallback |
| Native Home viewers creating a watched call | >= 20% | Eligible calls only |
| Watched calls receiving a later open or notification interaction | >= 25% | Separate push-driven and manual return |
| Watched windows receiving outcome feedback | >= 20% | Rating or explicit no-surf response |
| Native users active on 2+ days | >= 30% | Baseline 21.6% |
| Recent mature native week-one return | >= 15% | Baseline approximately 8% |

Targets are directional launch thresholds, not proof of product-market fit. The final report must include sample sizes and uncertainty.

## Guardrail Metrics

The phase does not pass if primary metrics improve while these deteriorate materially:

- Water-temperature/tide page useful-answer visibility.
- Organic impressions, CTR, average position, and canonical coverage on pilot pages.
- Core Web Vitals and route response time.
- Bounce and second-page behavior, interpreted by page intent.
- App Store handoff failure rate.
- Push permission denial, notification disable, unsubscribe, and app uninstall signals where available.
- Notification delivery error, duplicate, cooldown, and frequency-cap violations.
- Native cold-start-to-stable-hero time.
- Home recommendation replacement rate by cause.
- Support/Sentry errors for follow merge, link resolution, alert creation, and feedback persistence.
- Existing full session-log submit rate.

## Audience Segmentation Contract

Every web report must separate:

1. **General coastal utility** - intent unknown or non-surf.
2. **Surf-qualified web** - explicit surfing or defensible surf behavior.
3. **Existing Quiver web user** - signed in or joined to native identity.
4. **Unknown** - insufficient evidence; never folded into surf by default.

Every native report must separate:

1. New joined handoff users.
2. New organic native users.
3. Existing users.
4. Watched-call users.
5. Non-watch users.
6. Test/emulator accounts versus physical production users.

## Experiment Design

### Web Pilot

Use a limited set of high-traffic beach and beach-water-temperature templates.

Required cohorts:

- Follow CTA exposed.
- Matched holdout with current utility page and no follow CTA.
- Surf-qualified CTA exposed.
- Surf-qualified matched holdout or staggered rollout.

Assignment must be stable for the experiment window and recorded as a safe enum. Do not compare unrelated geographies/templates as if they were randomized.

### Native Watch Loop

Use a staged rollout only long enough to verify safety and instrumentation. The target production state is enabled for all users.

Required evidence:

- Home continuity and stability enabled.
- Watch CTA exposure and eligibility.
- Watch created versus not created.
- Notification type and delivery/open.
- Manual return independent of notification.
- Outcome prompt and response.
- D1/D7 and multi-day use by cohort.

Do not permanently withhold the Week Scout stability fix as an experiment after correctness is proven.

## Automated Validation Matrix

### Web Unit/Component

- Intent evidence classification: explicit, inferred, unknown, and conflict resolution.
- One water-temperature page view does not qualify surfing.
- Follow local-state versioning, add, remove, topic update, and corruption fallback.
- Anonymous -> account merge is idempotent and union-safe.
- Existing account follow removal remains authoritative when explicitly performed.
- My Coast content adapts by selected topics and intent.
- Utility answer renders before follow/app CTA.
- Exact handoff URL/token preserves beach/window/source context.
- Expired/invalid token renders a truthful fallback.
- Analytics events pass taxonomy/privacy validation.
- Canonical and structured-data output is unchanged for pilot pages.

### Web Integration/E2E

- Follow a beach anonymously, reload, and retain it.
- Follow multiple beaches and open My Coast.
- Sign in and merge without duplicates or loss.
- Unknown-intent water-temperature visitor sees a general follow action, not a dominant surf download CTA.
- Surf-qualified visitor opens an exact app link or App Store fallback.
- App-not-installed fallback preserves attribution token.
- Mobile 360/390/412, tablet, and desktop layouts remain usable.
- No JavaScript/local-storage failure hides the original utility answer.

### Native Unit/Component

- Home mode persists/restores within the bounded validity contract.
- Intentional mode expiry/reset is explicit and tracked.
- `Best` incumbent retains below the 10-point threshold.
- Material, unsafe, unrideable, skipped, missing, or passed incumbent replaces correctly.
- `Now` remains live and does not inherit Best stability.
- Change reason classifier distinguishes mode, location, candidates, filters, startup refinement, and forecast shift.
- Watch seed contains exact call context and reuses alert infrastructure.
- One-tap outcome validates 1-5 and supports offline/pending persistence.
- Learning receipt is generated only from actual saved effects.
- Full SessionForm remains reachable and receives the same context.

### Native Maestro/Device

- Night: select Best; cold-launch next morning; Best context restores while valid.
- Small refresh: same beach/window retained with updated details.
- Material refresh: new call appears with one change explanation.
- Location change: change is attributed to location, not forecast.
- Saved/excluded spot change: candidate-set reason is shown/tracked.
- Create Watch this call in one tap.
- Receive/open still-on notification on a physical production-configured device.
- Receive/open material-change notification on a controlled fixture or approved test path.
- Complete one-tap outcome, see truthful receipt, optionally open full log.
- Exact HTTPS web link opens the installed production/TestFlight app at the correct beach/window.
- App Store install/fallback first-open join is validated on a signed physical path when technically available.

## Analytics Verification

Before rollout, verify:

- Every new event is accepted by the web/native event taxonomy.
- Anonymous events are explicitly allowed where intended.
- No raw search text, email, notes, coordinates, notification text, or other PII is emitted.
- Handoff tokens are not used as unconstrained high-cardinality public analytics fields; use a join table or bounded identifiers as appropriate.
- Test/emulator traffic is filterable.
- Audience class, experiment, surface, beach ID, window ID, mode, reason enum, and outcome are queryable.
- Event delivery failure does not block follow, handoff, watch, or outcome actions.

Required saved PostHog insights or documented queries:

1. Web follow funnel by page type and audience.
2. My Coast repeat usage.
3. Surf-qualified exact-handoff funnel through native first open/context resolution.
4. Home mode/recommendation change reasons.
5. Watch creation -> notification/manual return -> outcome.
6. D1/D7 retention by joined/organic and watched/non-watch cohorts.
7. Notification quality and opt-out guardrails.
8. Page-intent/CWV/SEO guardrails for pilot routes.

## Performance Budgets

Planning must record concrete baselines and thresholds. Minimum contracts:

- Follow controls add no blocking server request to the first anonymous save.
- My Coast uses bounded followed beaches and avoids per-beach N+1 fetches.
- Pilot utility pages do not add a new blocking forecast fan-out above the existing route budget.
- Exact handoff generation is deterministic and cheap.
- Native watch creation does not require the advanced composer to render first.
- Native Home must not show a settled hero and then replace it solely because delayed candidate context arrived.
- Added native hydration must not regress cold-start-to-stable-hero beyond the approved threshold established in Plan 20.1-05.

## Production And Approval Gates

Explicit approval remains required before:

- applying a production database migration;
- deploying web/API changes;
- changing production aliases;
- sending real email or push notifications outside an approved test cohort;
- changing entitlements or payment behavior;
- publishing a new native build or OTA update;
- enabling a production flag that materially changes all-user behavior.

The Week Scout stability requirement is already directed toward all users, but the actual production build/update remains an approval-gated release action.

## Definition Of Done

Phase 20.1 is complete only when:

1. All BFR requirements are implemented or explicitly blocked with owner and next action.
2. Anonymous follow and signed-in merge work on the pilot web surfaces.
3. My Coast provides useful followed-beach changes without assuming surf intent.
4. Exact surf handoff joins through native and resolves the intended context.
5. Native Home continuity and all-user Week Scout stability are live and device-verified.
6. Watch this call creates a useful monitor in one tap and sends only approved decision-relevant updates.
7. One-tap outcome feedback persists and produces a truthful receipt.
8. Automated, E2E, device, analytics, and guardrail evidence passes.
9. Primary metrics improve enough to justify continued rollout without material guardrail regression.
10. Production changes and outbound actions were performed only with explicit approval.
