# Phase 20.1: Durable Beach Follow And Surf-Call Retention Loop - Research

**Researched:** 2026-08-24  
**Corrected:** 2026-08-24 after confirming one-tap native sessions were already shipped and did not move retention  
**Status:** Complete enough for execution planning  
**Evidence sources:** PostHog project 424662, current `quiver` and `quiver-native` source, native issues #55/#76/#155, prior Phase 20 app-link and measurement artifacts

## Executive Finding

Quiver has two different products with two different repeat-use problems:

- **Web** receives broad, mostly anonymous coastal utility traffic. Many visitors may be swimmers, travelers, anglers, paddlers, parents, or beachgoers rather than surfers.
- **Native** has a much smaller surf audience whose strongest repeated behavior is manually opening Home, Explore, and Beach Detail to check current or near-term conditions.

The AllTrails pattern translates as:

- durable object: trail -> beach;
- first ownership action: save trail -> follow beach;
- exact handoff: trail page -> exact beach/window;
- native differentiated job: navigation/conditions -> remember, monitor, and explain the accepted surf call.

The original research overextended the post-activity analogy. Native already has quick log, one-tap rating, session prefill, reminders, offline support, and the full session form. That work did not materially change retention or sales. Therefore the Phase 20.1 retention hypothesis is **not** another lightweight outcome or session flow.

The highest-leverage test is:

> Can Quiver create durable beach ownership on web, preserve the accepted native call, remain quiet when nothing meaningful changes, and earn an exact-context return when the surf decision changes?

### Existing quick-log evidence

Current event taxonomy already includes:

- `home_quick_log_tapped`;
- `session_log_start`;
- `session_log_rating_set`;
- `session_prefill_shown`;
- `session_log_submit`;

For physical-device users excluding test accounts from 2026-06-01 through 2026-08-23:

- 9 users tapped Home quick log;
- 4 submitted a session within one day.

This is not evidence that quick log caused return. It shows the feature exists and some adopters complete it. The product-level retention and sales trend did not move. Phase 20.1 therefore preserves the feature but removes session completion from its primary hypothesis and scorecard.

## Corrected AllTrails Translation

AllTrails' durable lifecycle is:

```text
Find trail -> save -> organize -> exact native trail -> use outside -> history/review
```

Quiver's Phase 20.1 lifecycle is:

```text
Find beach utility
  -> follow beach
  -> qualify surf intent only when evidence exists
  -> exact beach/window handoff
  -> preserve accepted Home mode/call
  -> watch call
  -> suppress update when nothing meaningful changed
  -> deliver still-on/material-change/better-nearby when justified
  -> reopen exact prior/current context
  -> measure useful return and mature retention
```

Existing quick log/session logging remains available independently. It is not required to complete this loop.

## Recommended Contracts

### Beach follow

Needs canonical beach identity, bounded selected topics, versioned local state, source surface, timestamps, and an idempotent anonymous-to-account merge. First anonymous save remains local and non-blocking.

### Intent evidence

Use `explicit`, `inferred`, and `unknown`; explicit choice wins. One water-temperature/tide/weather view never qualifies surfing. Persist safe enums/counts only.

### Exact surf handoff

Carry beach/window/recommendation identity, source page class, anonymous join identity, created/expiry time, and truthful fallback. Native resolves current truth while preserving prior context for explanation.

### Watched call

Extend existing alert/recommendation identity with beach, window, mode, accepted scorer/forecast context, state, last evaluation, and history.

### Meaningful update

Use a bounded type:

- `still_on`;
- `material_change`;
- `better_nearby`;
- `none`/suppressed.

Every update requires prior/current identity, actual cause, dedupe key, freshness, and exact reopen target. No-change evaluation preserves the watch without sending a push.

### Existing sessions

No new contract. The audit records existing entry sources, attribution fields, quick-log events, full-session behavior, and optional watched-call attribution seam. Existing event names remain secondary diagnostics.

## Measurement Model

Primary native funnel:

```text
eligible call
  -> watch CTA exposure
  -> watch created
  -> meaningful update eligible OR manual watch revisit
  -> update delivered/opened OR manual reopen
  -> exact context resolved
  -> later mature return
```

Required separation:

- notification-driven vs manual return;
- watched vs eligible-unwatched;
- new joined handoff vs organic native vs existing users;
- physical production vs emulator/test;
- update eligible vs no meaningful change;
- general coastal web vs surf-qualified web.

Quick-log/session starts/submits remain a historical baseline and non-regression guardrail only.

## Risks

1. **Manufactured notification volume:** stable conditions may produce few updates. That is acceptable; do not lower thresholds to create activity.
2. **Self-selection:** surfers who watch are already high intent. Use stable holdout/stagger assignment and mature cohorts.
3. **Recommendation churn:** mode, GPS, candidate, filter, and refresh changes can masquerade as forecast intelligence. Fix/classify continuity first.
4. **Release ambiguity:** native `main` is not proof of the distributed bundle. Record exact binary/runtime/channel/update/source/flag truth.
5. **Web audience pollution:** Follow/My Coast must stay useful to non-surf visitors.
6. **Duplicate systems:** reuse one favorite/follow model, one router, one alert/watch history, and one analytics path.
7. **Session distraction:** do not allow the existing quick-log investment to pull the phase back toward another session-friction project.

## Recommendation

Proceed with Phase 20.1 only after the inflight/release audit resolves direct file and branch conflicts.

Prioritize:

1. Web beach ownership and My Coast.
2. Exact surf-qualified handoff.
3. Native Home continuity and all-user Week Scout stability.
4. One-tap Watch this call.
5. Quiet evaluation plus meaningful exact-context updates.
6. Causal/guardrail evidence of useful return.

Do not build a new one-tap outcome/session feature in this phase.
