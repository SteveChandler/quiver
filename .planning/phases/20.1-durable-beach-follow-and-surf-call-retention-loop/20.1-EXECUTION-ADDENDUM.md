## Global execution rules

### Release truth before implementation truth

Before editing code, record whether the reused capability is on `main`, in web `prod`, in the distributed native binary/OTA, migration-applied, flag-enabled in the actual bundle, and live/device-verified. `Merged` is not a release status.

### Local/worktree truth before branch assumptions

`claude/tech-debt-audit-codex-973g1t` was not visible as a pushed ref in the connected Quiver repositories when it was added to this workflow. Treat it as local/worktree-only until proven otherwise.

Before native contract or implementation work:

- identify its repository and worktree;
- capture head SHA, merge base, ahead/behind, committed and uncommitted files;
- reconcile its issues/research with the current collision map;
- disposition each logical slice as reference-only, land audit artifacts, bounded cherry-pick, separate rebased PR, superseded, or retire;
- reserve every overlapping file until ownership is explicit.

Do not blindly merge the branch and do not delete its worktree before durable artifacts are pushed or exported.

### Mock state before visual implementation

Capture or fixture the current shipping state corresponding to each mock, then compare hierarchy, copy semantics, state transitions, prior/current context, accessibility, responsive/dynamic-type behavior, and degraded behavior after implementation. Document every intentional deviation.

### Existing sessions are preserve-only baseline

Native already has Home quick log, one-tap rating entry, session prefill, reminders, offline behavior, and full SessionForm. PostHog already records that funnel. The observed physical-device/test-excluded baseline from 2026-06-01 through 2026-08-23 is nine Home quick-log users and four one-day submitters, while product retention/sales did not materially improve.

Therefore Phase 20.1 must not add:

- a watched-call 1–5 prompt;
- a learning receipt;
- a post-window session reminder;
- a new session/outcome schema;
- a parallel session history;
- new outcome events presented as the phase's retention funnel.

Existing session paths may accept watched-call attribution only through an already-audited seam when the user independently chooses to log. Session activity is secondary/non-regression evidence.

### No opportunistic scope absorption

Keep native social-share PR #131, profile sharing, App Store PPO, broad map work, lifecycle-email redesign, Phase 21 implementation, and unrelated performance/debt cleanup on their own release lanes unless a direct BFR blocker is proven and recorded.

The tech-debt branch is a workflow input, not permission to absorb every audit finding into Phase 20.1. Only a directly required BFR blocker may land in the phase; coherent independent remediation must be rebased into its own PR.
