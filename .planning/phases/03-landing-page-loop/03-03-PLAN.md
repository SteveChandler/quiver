# Plan 03-03: iOS CTA And Event Normalization

## Metadata

- Phase: 03 - Landing Page Loop
- Plan: 03-03
- Status: complete
- Executed: 2026-05-24
- Mode: implementation
- Requirements: LAND-01, LAND-04, LAND-05, ANLY-01

## Objective

Normalize the active landing iOS CTA copy and analytics semantics so launch traffic uses one App Store destination, no stale pre-order language, and measurable CTA events without adding a database migration.

## Implementation Scope

- Replace stale public pre-order copy and metadata with a shared status-neutral App Store listing source of truth.
- Normalize landing App Store CTA event names to `ios_app_cta_view` and `ios_app_cta_click`.
- Mirror iOS CTA views/clicks into existing internal `cta_impression` and `cta_click` events using existing anonymous-allowed `/api/events` behavior.
- Preserve authenticated-user CTA guards and pre-auth signup event rules.
- Keep pricing, checkout, lifetime, RevenueCat Web Billing, and App Store status verification out of scope.
- Perform a local desktop/mobile visual review for the touched CTA surfaces.

## Non-Goals

- No Supabase migration or `user_events` CHECK constraint expansion.
- No App Store Connect, RevenueCat dashboard, Vercel env, or production data changes.
- No hero video/poster asset replacement.
- No pricing/founding-offer UI.
- No final App Store/TestFlight truth gate; that remains Phase 7.
