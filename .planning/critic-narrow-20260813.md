## Migration assessment

- **Transactional:** Yes. The migration has `BEGIN` and `COMMIT` around table creation, seed, RLS, grants, and schema reload (`supabase/migrations/20260813140000_create_water_quality_held_beaches.sql:3-35`).
- **Seed:** The five literal UUIDs match the five-code manifest (`supabase/migrations/20260813140000_create_water_quality_held_beaches.sql:11-25`, `lib/recommendations/major-event-hold/water-quality.ts:10-17`), but the migration deliberately skips IDs absent from `beaches` and emits only a warning for a shortfall (`supabase/migrations/20260813140000_create_water_quality_held_beaches.sql:21-48`). The FK protects rows that are inserted (`supabase/migrations/20260813140000_create_water_quality_held_beaches.sql:5-9`); it does not guarantee the five required rows.
- **RLS:** Sane for the intended server-only owner table: RLS is enabled and only `service_role` is granted table DML (`supabase/migrations/20260813140000_create_water_quality_held_beaches.sql:27-31`); runtime resolution uses the service-role client (`lib/recommendations/major-event-hold/water-quality.ts:118-125`).
- **Before apply:** Direct beach pages remain visible because they do not depend on this table (`app/beach/[slug]/page.tsx:41-47`, `app/beach/[slug]/page.tsx:66-88`), but WQ-enabled recommendation lists and canonical discovery fail closed as described above (`lib/recommendations/major-event-hold/water-quality.ts:127-146`, `lib/recommendations/major-event-hold/water-quality-visibility.ts:99-106`, `app/api/surf/discover/route.ts:291-300`). That is not a usable before/after rollout state for the recommendation product.
- **After apply:** The table shape, FK, seed, RLS, and service-role read path line up (`supabase/migrations/20260813140000_create_water_quality_held_beaches.sql:5-31`, `lib/recommendations/major-event-hold/water-quality.ts:118-185`). The migration is a one-shot forward migration rather than a rerunnable script because `CREATE TABLE` is not `IF NOT EXISTS` (`supabase/migrations/20260813140000_create_water_quality_held_beaches.sql:5-9`); that is normal for migration runners, but it reinforces that the unapplied state cannot be treated as a functioning deployment.
