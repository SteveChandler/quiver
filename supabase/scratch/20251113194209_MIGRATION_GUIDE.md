# Migration Guide: Add Session Details Fields

**Migration File:** `20251113194209_add_session_details_fields.sql`
**Created:** 2025-11-13
**Status:** Ready for Deployment

---

## Executive Summary

This migration adds 4 new columns to the `sessions` table to capture session condition details that were previously collected in the UI but never saved to the database. This fixes a critical data loss issue identified by code archaeology analysis.

### Fields Added

| Column Name | Type | Nullable | Description |
|------------|------|----------|-------------|
| `wave_height_ft` | DECIMAL(4,1) | YES | Actual wave height in feet (0-100) |
| `wind_speed_mph` | INTEGER | YES | Wind speed in mph (0-200) |
| `wind_direction` | TEXT | YES | Wind direction (N, NE, E, SE, S, SW, W, NW, OFFSHORE, ONSHORE, CROSS) |
| `forecast_accuracy` | TEXT | YES | Forecast accuracy feedback (accurate, somewhat, inaccurate) |

### Impact Assessment

- **Breaking Changes:** None
- **Data Loss Risk:** None (all columns nullable)
- **Backward Compatibility:** Full
- **Performance Impact:** Minimal (partial indexes only on non-null values)
- **RLS Policy Impact:** None (columns inherit table-level policies)

## Troubleshooting

### Issue: Constraint violation errors

**Symptom:** Users getting errors when submitting sessions

**Diagnosis:**
```sql
-- Check for invalid data being submitted
SELECT
  id,
  wave_height_ft,
  wind_speed_mph,
  forecast_accuracy
FROM sessions
WHERE
  wave_height_ft < 0 OR wave_height_ft > 100 OR
  wind_speed_mph < 0 OR wind_speed_mph > 200 OR
  forecast_accuracy NOT IN ('accurate', 'somewhat', 'inaccurate', NULL);
```

**Solution:** Add validation in application layer before database insert.

### Issue: Performance degradation

**Symptom:** Slower queries on sessions table

**Diagnosis:**
```sql
-- Check index usage
EXPLAIN ANALYZE
SELECT *
FROM sessions
WHERE wave_height_ft > 3
  AND beach_id = '[some-beach-id]';
```

**Solution:** Indexes should be used automatically. If not, check query patterns.

### Issue: Type generation fails

**Symptom:** `yarn db:types` produces errors

**Diagnosis:** Check Supabase connection and credentials

**Solution:**
```bash
# Verify connection
npx supabase status

# Reconnect if needed
npx supabase link --project-ref [PROJECT_REF]

# Retry type generation
yarn db:types
```
