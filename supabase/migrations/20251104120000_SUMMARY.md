## Problem Statement

The onboarding flow in `actions/onboarding-actions.ts` (lines 48-77) allows users to enter referral codes, but the database infrastructure didn't exist. The code was attempting to:

1. Look up a referrer by `profiles.referral_code` (column didn't exist)
2. Create a record in the `referrals` table (table didn't exist)

This migration creates all necessary infrastructure to support this feature.

---

## What Was Created

### 1. Database Schema

#### **profiles.referral_code Column**
```sql
ALTER TABLE public.profiles ADD COLUMN referral_code TEXT;
```
- **Type**: TEXT
- **Nullable**: YES (populated on first access)
- **Unique**: Case-insensitive uniqueness enforced via index
- **Purpose**: Each user gets their own code to share with friends

#### **referrals Table**
```sql
CREATE TABLE public.referrals (
    id UUID PRIMARY KEY,
    referrer_id UUID NOT NULL,      -- Who shared the code
    referee_id UUID NOT NULL,        -- Who used the code
    referral_code TEXT NOT NULL,     -- The actual code entered
    status TEXT NOT NULL,            -- pending/completed/expired
    completed_at TIMESTAMPTZ,        -- When completed
    created_at TIMESTAMPTZ NOT NULL,
    updated_at TIMESTAMPTZ NOT NULL
);
```

### 2. Constraints & Validation

| Constraint | Purpose | Error Prevented |
|------------|---------|-----------------|
| `referrals_no_self_referral` | referrer_id ≠ referee_id | Users can't refer themselves |
| `referrals_unique_referee` | UNIQUE(referee_id) | Users can only be referred once |
| `referrals_completed_at_when_completed` | Status validation | Completed status must have timestamp |
| `idx_profiles_referral_code_lower` | UNIQUE LOWER(code) | Case-sensitive duplicates |

### 3. Indexes (7 Total)

| Index Name | Columns | Type | Purpose |
|------------|---------|------|---------|
| `idx_profiles_referral_code_lower` | LOWER(referral_code) | UNIQUE | Case-insensitive uniqueness |
| `idx_profiles_referral_code` | referral_code | B-tree | Fast profile lookups |
| `idx_referrals_code_lower` | LOWER(referral_code) | B-tree | Fast code searches |
| `idx_referrals_referrer_id` | referrer_id | B-tree | Referrer stats queries |
| `idx_referrals_referee_id` | referee_id | B-tree | Check if user referred |
| `idx_referrals_status` | status | B-tree | Filter by status |
| `idx_referrals_referrer_status` | (referrer_id, status) | Composite | Stats aggregations |
| `idx_referrals_created_at` | created_at DESC | B-tree | Recent referrals |

### 4. RLS Policies (4 Total)

| Policy | Operation | Rule |
|--------|-----------|------|
| "Users can view own referrals as referrer" | SELECT | auth.uid() = referrer_id |
| "Users can view own referrals as referee" | SELECT | auth.uid() = referee_id |
| "Users can create referrals for themselves" | INSERT | auth.uid() = referee_id |
| "Users can update own referrals as referee" | UPDATE | auth.uid() = referee_id |

**Note**: No DELETE policy - referrals are immutable for audit purposes.

### 5. Helper Functions

#### **generate_referral_code()**
```sql
RETURNS TEXT
```
- Generates unique 6-character alphanumeric code (uppercase)
- Case-insensitive uniqueness check
- Max 10 generation attempts to avoid collisions
- Example output: `A3X9K2`, `B7F2J8`

#### **get_user_referral_stats(user_id UUID)**
```sql
RETURNS TABLE (
    total_referrals BIGINT,
    completed_referrals BIGINT,
    pending_referrals BIGINT,
    expired_referrals BIGINT,
    referral_code TEXT
)
```
- Returns aggregated referral statistics for a user
- Useful for leaderboards, analytics, profile displays

### 6. Triggers

- **update_referrals_updated_at**: Automatically updates `updated_at` on row modifications

## Performance Characteristics

### Query Performance (Expected)

| Query Type | Index Used | Expected Time | Benchmark |
|------------|-----------|---------------|-----------|
| Find referrer by code | `idx_profiles_referral_code_lower` | <5ms | P95 <10ms |
| Check if user referred | `idx_referrals_referee_id` | <5ms | P95 <10ms |
| User referral stats | `idx_referrals_referrer_status` | <10ms | P95 <20ms |
| Recent referrals | `idx_referrals_created_at` | <10ms | P95 <20ms |

### Storage Impact

- **profiles.referral_code**: ~10 bytes per user
- **referrals table**: ~100 bytes per referral
- **Indexes**: ~50 bytes per record × 7 indexes
- **Estimated for 1000 users with 20% referral rate**:
  - profiles column: 10KB
  - referrals table: 20KB
  - indexes: 7KB
  - **Total**: ~37KB (negligible)

## Security Features

### 🔒 Data Protection

1. **RLS Enabled**: All queries filtered by user identity
2. **No Mass Data Access**: Users can only see their own referrals
3. **Audit Trail**: Referrals are immutable (no DELETE policy)
4. **Self-Referral Prevention**: Check constraint blocks gaming
5. **Unique Referee**: Prevents multiple referral bonuses

### 🔒 Function Security

- `SECURITY DEFINER` with explicit `search_path = public`
- Prevents search_path exploitation attacks
- Follows Supabase security best practices

### 🔒 Injection Prevention

- All constraints use PostgreSQL native checks
- No dynamic SQL in functions
- Parameterized queries required at application level

## Rollback Procedure

If issues arise, execute the following SQL:

```sql
-- Drop referrals table and cascade to dependent objects
DROP TABLE IF EXISTS public.referrals CASCADE;

-- Remove referral_code column from profiles
ALTER TABLE public.profiles DROP COLUMN IF EXISTS referral_code;

-- Drop helper functions
DROP FUNCTION IF EXISTS public.generate_referral_code();
DROP FUNCTION IF EXISTS public.get_user_referral_stats(UUID);

-- Note: Indexes and triggers are automatically dropped with CASCADE
```

**Estimated rollback time**: <1 second (idempotent, no data dependencies)

**Dashboard Queries:**
```sql
-- Daily referral signups
SELECT DATE(created_at), COUNT(*), status
FROM referrals
WHERE created_at >= NOW() - INTERVAL '7 days'
GROUP BY DATE(created_at), status
ORDER BY DATE(created_at) DESC;

-- Top referrers
SELECT
    p.display_name,
    COUNT(*) AS total_referrals,
    COUNT(*) FILTER (WHERE r.status = 'completed') AS completed
FROM referrals r
JOIN profiles p ON p.id = r.referrer_id
GROUP BY p.id, p.display_name
ORDER BY completed DESC
LIMIT 10;

-- Referral conversion funnel
SELECT
    status,
    COUNT(*) AS count,
    ROUND(COUNT(*) * 100.0 / SUM(COUNT(*)) OVER (), 2) AS percentage
FROM referrals
GROUP BY status;
```
